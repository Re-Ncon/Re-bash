# Re-bash
Скрипт `Re-bash` представляет собой комплексную утилиту (Bash-скрипт) для автоматизации администрирования, настройки и развертывания программного обеспечения на серверах и рабочих станциях (АРМ) под управлением ОС Astra Linux 1.6.*-1.7.*

## 📥 Установка и запуск

Вам не обязательно скачивать весь репозиторий, достаточно загрузить сам исполняемый файл скрипта.

### 1. Скачивание скрипта
Загрузите скрипт на рабочую станцию с помощью утилиты `wget` (файл сохранится как `Re_bash.sh`):
```bash
wget -O Re_bash.sh [https://raw.githubusercontent.com/Re-Ncon/Re-bash/main/Re%20bash.sh](https://raw.githubusercontent.com/Re-Ncon/Re-bash/main/Re%20bash.sh)
chmod +x Re_bash.sh
sudo ./Re_bash.sh
```

## 📋 Важные инструкции и особенности работы

Перед началом работы со скриптом **RENCON** обязательно ознакомьтесь со следующими правилами и механиками его работы:

### 👑 1. Запуск с правами суперпользователя (root)
Скрипт выполняет глубокую настройку ОС: изменяет системные конфигурационные файлы (в `/etc/`), управляет службами (`systemctl`), устанавливает пакеты и настраивает сеть.
*   **Требование:** Скрипт должен выполняться **строго с правами root**.
*   **Как запускать:** Используйте команду `sudo ./rencon.sh` или предварительно перейдите в сеанс суперпользователя с помощью `sudo su` / `su -`. При запуске от обычного пользователя скрипт не сможет применить настройки.

### 📦 2. Для чего нужны `.deb` файлы?
Скрипт **автоматизирует** процесс установки, настройки и исправления ошибок, но он **не скачивает** проприетарное программное обеспечение (такое как Kaspersky, Dr.Web или Jacarta) из интернета. 
*   **Причина:** Это сделано специально для возможности работы в изолированных корпоративных сетях (без выхода в интернет), а также из-за лицензионных ограничений самих продуктов.
*   **Что делать администратору:** Для работы модулей установки ПО вы должны заранее скачать нужные `.deb` пакеты (например, `kesl_*.deb`, `klnagent_*.deb` или пакеты Jacarta) и положить их в директорию рядом со скриптом. Утилита сама найдет их и запустит тихую установку.

### 📝 3. Система логирования (Журналы работы)
Вам не придется гадать, успешно ли отработал скрипт или на каком ПК возникла проблема — утилита ведет подробный учет действий.
*   **Где сохраняются:** Лог-файлы генерируются автоматически и сохраняются прямо в рабочей директории скрипта.
*   **Что внутри логов:**
    *   **Сетевая диагностика:** При использовании массового пинга (модуль 7) создаются файлы вида `ping_log_*.log`, где зафиксированы все ответившие и недоступные IP-адреса.
    *   **Установка ПО:** При установке пакетов (например, Jacarta) вывод терминала перенаправляется в инсталляционные логи (например, `jacarta_install_*.log`). Это позволяет легко отследить ошибки зависимостей или нехватку места на диске.
*   **Очистка:** Вы можете безболезненно удалять эти `.log` файлы после завершения работы — при необходимости скрипт сгенерирует новые.
